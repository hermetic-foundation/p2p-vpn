# Quick Start

This guide creates a minimal two-node overlay.

The default profile uses mDNS, public IPFS-compatible Kademlia bootstrap,
provider discovery, DCUtR, and AutoNAT.

## What You Need

| Item | Node A | Node B |
| --- | --- | --- |
| Built `p2p-vpn` binary | yes | yes |
| Root or `CAP_NET_ADMIN` | yes | yes |
| Unique config file | `host-a.json` | `host-b.json` |
| Peer ID and private key | generated by config | generated by config |
| Remote peer ID | Node B ID | Node A ID |

These are enough for an authorized overlay peer.

Add explicit addresses only when discovery is not enough.

Add explicit IP routes only when you want chosen VPN IPs.

Otherwise, p2p-vpn derives built-in host IPs from peer IDs.

## Minimum Config Concept

At the protocol level, a peer entry can be just an ID:

```json
{
  "network": {
    "name": "lab",
    "local_peer": "LOCAL_PEER_ID",
    "private_key": "BASE64_PRIVATE_KEY"
  },
  "peers": [
    { "id": "REMOTE_PEER_ID" }
  ]
}
```

Defaults fill in:

| Field | Default |
| --- | --- |
| TUN interface | `pv0` |
| MTU | `1280` |
| libp2p listener | `/ip4/0.0.0.0/tcp/4001` |
| Discovery | mDNS, public Kademlia, provider ads, DCUtR, AutoNAT |
| Public bootstrap | built-in IPFS/libp2p bootstrap peers |
| Queue and resource limits | built-in safe defaults |
| Packet plane listeners | disabled unless configured |

For predictable VPN addresses, add only route ownership.

This is the "ID plus IP" shape:

```json
{
  "network": {
    "name": "lab",
    "local_peer": "LOCAL_PEER_ID",
    "private_key": "BASE64_PRIVATE_KEY",
    "routes": [{ "prefix": "10.44.0.1/32" }]
  },
  "peers": [
    {
      "id": "REMOTE_PEER_ID",
      "routes": [{ "prefix": "10.44.0.2/32" }]
    }
  ]
}
```

If discovery cannot find the peer, add only the LAN IP:

```json
{
  "id": "REMOTE_PEER_ID",
  "ip": "REMOTE_IP",
  "routes": [{ "prefix": "10.44.0.2/32" }]
}
```

Use `addresses` only for non-default ports or relayed multiaddrs.

## 1. Build The Binary

```sh
nix build
```

Use the flake app during development:

```sh
nix run .# -- --help
```

## 2. Generate A Config On Each Host

`init-config` writes compact JSON.

Defaulted discovery and resource sections are omitted.

Run this on Node A:

```sh
nix run .# -- init-config \
  --output host-a.json \
  --network lab \
  --interface pv0 \
  --force
```

Run this on Node B:

```sh
nix run .# -- init-config \
  --output host-b.json \
  --network lab \
  --interface pv0 \
  --force
```

## 3. Get Each Peer ID

On Node A:

```sh
nix run .# -- status --config host-a.json
```

On Node B:

```sh
nix run .# -- status --config host-b.json
```

Copy each `local peer` value.

## 4. Add Peers

Regenerate or edit each config so it contains the other peer.

The smallest peer entry is just the remote peer ID.

Use routes only when you want stable overlay IPs:

```text
--peer PEER_ID
--peer-route PEER_ID=CIDR
```

Example for Node A:

```sh
nix run .# -- init-config \
  --output host-a.json \
  --network lab \
  --peer NODE_B_PEER_ID \
  --peer-route NODE_B_PEER_ID=10.44.0.2/32 \
  --local-route 10.44.0.1/32 \
  --force
```

Example for Node B:

```sh
nix run .# -- init-config \
  --output host-b.json \
  --network lab \
  --peer NODE_A_PEER_ID \
  --peer-route NODE_A_PEER_ID=10.44.0.1/32 \
  --local-route 10.44.0.2/32 \
  --force
```

Use explicit addresses only as overrides:

```text
--peer PEER_ID=/ip4/HOST/tcp/PORT/p2p/PEER_ID
```

Do not hardcode relayed circuit paths for normal operation.

## 5. Start The Daemon

Run this on each node:

```sh
sudo ./result/bin/p2p-vpn up \
  --config host-a.json \
  --control-socket /run/p2p-vpn.sock
```

Use `host-b.json` on Node B.

## 6. Check Health

```sh
sudo ./result/bin/p2p-vpn daemon-health \
  --socket /run/p2p-vpn.sock \
  --require-validated-peers \
  --require-supported-paths \
  --wait-seconds 30
```

## 7. Test Traffic

From Node A:

```sh
ping -I pv0 10.44.0.2
```

From Node B:

```sh
ping -I pv0 10.44.0.1
```

## Stop The Daemon

```sh
sudo ./result/bin/p2p-vpn daemon-shutdown \
  --socket /run/p2p-vpn.sock
```
