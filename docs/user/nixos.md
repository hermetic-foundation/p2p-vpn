# NixOS Module

The flake exports `nixosModules.default`.

Use one named instance for each overlay network.

## Quick Start

### 1. Add the Input

```nix
{
  inputs.p2p-vpn.url = "github:hermetic-foundation/p2p-vpn";
}
```

### 2. Import the Module

```nix
{ inputs, ... }:
{
  imports = [ inputs.p2p-vpn.nixosModules.default ];
}
```

### 3. Declare a Network

Add the same instance name on each host:

```nix
{
  services.p2p-vpn.instances.runners = {
    enable = true;
    dns.enable = true;
  };
}
```

Apply the configuration:

```sh
sudo nixos-rebuild switch
```

This creates a working node with a persistent identity.

It does not trust another overlay member until you pair or configure one.

### 4. Pair the Hosts

On an existing member:

```sh
sudo p2p-vpn pair open --instance runners
```

Record the operation ID and pairing code.

On the joining host:

```sh
sudo p2p-vpn pair join CODE \
  --instance runners \
  --no-wait
```

Inspect and approve the candidate on the existing member:

```sh
sudo p2p-vpn pair status OPEN_OPERATION --instance runners
sudo p2p-vpn pair approve \
  OPEN_OPERATION APPROVAL_ID \
  --instance runners
```

Render a local Nix fragment on each host:

```sh
sudo p2p-vpn pair artifacts LOCAL_OPERATION \
  --instance runners \
  --output /etc/nixos/p2p-vpn-runners-paired.nix \
  --force
```

Import the local generated file:

```nix
{
  imports = [ ./p2p-vpn-runners-paired.nix ];
}
```

Apply it:

```sh
sudo nixos-rebuild switch
```

Both receipt digests must match.

See [Pairing](pairing.md) for verification, acknowledgment, and offline fallback.

## Default Profile

Defaults are assigned by the sorted native instance index `N`.

| Resource | Default |
| --- | --- |
| Network name | Instance name |
| Identity | `/var/lib/p2p-vpn/<instance>/private.key` |
| Pairing state | `/var/lib/p2p-vpn/<instance>/pairing-state.json` |
| Learned membership | `/var/lib/p2p-vpn/<instance>/membership-state.json` |
| DNS hostname | `networking.hostName` |
| DNS zone | `<instance>.p2p-vpn.internal` |
| Interface | `pvN` |
| TUN MTU | `1280` |
| libp2p TCP | `0.0.0.0:4001+N` |
| libp2p QUIC | `0.0.0.0:4001+N` |
| UDP packet plane | `0.0.0.0:51820+N` |
| Control socket | `/run/p2p-vpn-<instance>/control.sock` |
| LAN discovery | mDNS |
| Public discovery | IPFS-compatible Kademlia |
| NAT traversal | AutoNAT and DCUtR |
| Relay fallback | Automatic relay candidates |
| Firewall | Required derived ports are opened |

DNS is opt-in. With `dns.enable = true`, the module configures per-link split
DNS and a search domain through `systemd-resolved`.

Pin interface and port options before changing instance names or adding an
instance that sorts before an existing one.

## Configuration Modes

Each instance uses exactly one mode.

| Mode | Configuration source | Secret handling |
| --- | --- | --- |
| Native Nix | Typed instance options | Automatic state or credential files |
| JSON | `configFile` only | Entirely owned by that JSON workflow |

Native mode may not be combined with `configFile`.

The module rejects mixed mode during NixOS evaluation.

### Native Nix Mode

```nix
{
  services.p2p-vpn.instances.lab = {
    enable = true;
    vpnIp = "10.44.0.1";
  };
}
```

The `/run/p2p-vpn-lab/config.json` file is a private runtime artifact.

It is generated by the module and is not a user configuration source.

### JSON Mode

```nix
{
  services.p2p-vpn.instances.lab = {
    enable = true;
    configFile = "/run/secrets/p2p-vpn-lab.json";
  };
}
```

The file must be absolute and outside `/nix/store`.

The module validates it, then passes it to the daemon without merging Nix settings.

## Identities and Secrets

### Automatic Identity

Native mode creates the identity on first service start:

```text
/var/lib/p2p-vpn/<instance>/private.key
```

The directory is mode `0700` and the key is mode `0600`.

Restarting or rebuilding does not rotate the identity.

### External Identity

Use a runtime secret path to manage the key elsewhere:

```nix
{
  services.p2p-vpn.instances.lab.privateKeyFile =
    "/run/secrets/p2p-vpn-lab.key";
}
```

The module passes this file through a systemd credential.

It does not copy the key into the Nix store.

With agenix:

```nix
{ config, ... }:
{
  age.secrets.p2p-vpn-lab-identity.file =
    ./secrets/p2p-vpn-lab-identity.age;

  services.p2p-vpn.instances.lab.privateKeyFile =
    config.age.secrets.p2p-vpn-lab-identity.path;
}
```

Code pairing reuses the daemon's active agenix-backed identity.

No private key is copied into the generated pairing fragment.

### Membership Key

The shared membership key is optional:

```nix
{
  services.p2p-vpn.instances.lab.membershipKeyFile =
    "/run/secrets/p2p-vpn-lab.membership-key";
}
```

Pairing can exchange this key and also issues a signed member record.

Do not place private keys or membership keys in Nix strings.

### Learned Membership

Native mode always persists learned signed records at:

```text
/var/lib/p2p-vpn/<instance>/membership-state.json
```

No module option or generated JSON is required.

The daemon restores derived members and routes before normal network processing.

Declarative `memberRecords` remain trust anchors; learned records remain service state.

## Stable Overlay Addresses

Pairing can use the built-in address derived from each peer ID.

Set `vpnIp` when services need a memorable address:

```nix
{
  services.p2p-vpn.instances.lab.vpnIp = "10.44.0.1";
}
```

Request the joining address during pairing:

```sh
sudo p2p-vpn pair join CODE \
  --instance lab \
  --vpn-ip 10.44.0.2
```

The inviter sees the request before approval.

For static authorization, assign both sides explicitly:

```nix
{
  services.p2p-vpn.instances.lab = {
    enable = true;
    vpnIp = "10.44.0.1";

    peers."REMOTE_PEER_ID" = {
      vpnIp = "10.44.0.2";
    };
  };
}
```

## Routes

Use `routes` for prefixes originated by the local node:

```nix
{
  services.p2p-vpn.instances.lab.routes = [
    "10.80.0.0/24"
    {
      prefix = "fd80::/64";
      metric = 100;
    }
  ];
}
```

Authorize static remote prefixes under the peer:

```nix
{
  services.p2p-vpn.instances.lab.peers."REMOTE_PEER_ID".routes = [
    "10.81.0.0/24"
  ];
}
```

Pairing places requested routes in an inviter-signed member record.

Conflicting address and route ownership is rejected.

## Discovery and Recovery

Leave discovery unset for normal deployments.

| Recovery stage | Mechanism |
| --- | --- |
| Same LAN | mDNS discovers direct addresses first |
| Public network | Kademlia finds peer and relay records |
| Restricted NAT | Circuit relay carries the fallback path |
| Upgrade available | DCUtR attempts a direct path |
| LAN returns | Direct LAN paths are promoted again |

Override discovery for controlled environments:

```nix
{
  services.p2p-vpn.instances.lab.discovery = {
    mdns = true;
    kademlia = false;
    kademliaProviderAdvertisement = false;
    dcutr = false;
    autonat = false;
  };
}
```

Do not hardcode a changing peer address unless it is an intentional bootstrap hint.

## Relay Configuration

Provide relay service from an infrastructure node:

```nix
{
  services.p2p-vpn.instances.relay = {
    enable = true;
    relayServer = true;
  };
}
```

Reserve a known relay only when automatic discovery is unsuitable:

```nix
{
  services.p2p-vpn.instances.lab.relayReservations = [
    "/ip4/203.0.113.10/tcp/4001/p2p/RELAY_ID/p2p-circuit"
  ];
}
```

Tune automatic selection with `autoRelay`:

```nix
{
  services.p2p-vpn.instances.lab.autoRelay = {
    maxCandidates = 16;
    maxReservations = 2;
    retryIntervalSeconds = 30;
  };
}
```

## Packet Plane

The default packet plane uses owned UDP datagrams.

QUIC DATAGRAM may be configured as an additional owned transport:

```nix
{
  services.p2p-vpn.instances.lab.packetPlane = {
    listen = [ "0.0.0.0:51820" ];
    quicListen = [ "0.0.0.0:51821" ];
  };
}
```

Use `externalEndpoints` or `quicExternalEndpoints` only for known public mappings.

An empty `listen` list disables the owned UDP listener.

## Multiple Networks

Each instance has separate identity, interface, ports, state, and service:

```nix
{
  services.p2p-vpn.instances = {
    runners.enable = true;
    storage.enable = true;
  };
}
```

| Instance | Unit | State |
| --- | --- | --- |
| `runners` | `p2p-vpn-runners.service` | `/var/lib/p2p-vpn/runners` |
| `storage` | `p2p-vpn-storage.service` | `/var/lib/p2p-vpn/storage` |

The module does not route traffic between instances.

Enable OS forwarding and firewall policy separately when inter-network routing is intentional.

## Firewall

`openFirewall = true` is the default.

The module derives TCP, QUIC, packet-plane, and mDNS ports from native settings.

Disable automatic rules:

```nix
{
  services.p2p-vpn.instances.lab.openFirewall = false;
}
```

Use these overrides for non-derivable JSON or custom transport ports:

| Option | Purpose |
| --- | --- |
| `tcpPorts` | Complete TCP port override |
| `udpPorts` | Complete transport UDP override |
| `packetPlaneUdpPorts` | Additional owned UDP ports |
| `packetPlaneQuicPorts` | Additional owned QUIC ports |

## Service Controls

Map configured networks to interfaces and peer IDs:

```sh
sudo p2p-vpn instance list
sudo p2p-vpn instance show lab
```

`instance show` derives the peer ID from the active runtime identity. It never
prints the private key or membership key.

```sh
sudo systemctl status p2p-vpn-lab.service
sudo p2p-vpn daemon-health \
  --socket /run/p2p-vpn-lab/control.sock \
  --require-validated-peers \
  --require-supported-paths
sudo journalctl -u p2p-vpn-lab.service
```

Set `metricsIntervalSeconds` to emit periodic metrics to the journal.

Set `controlSocket = null` to disable local daemon control commands.

## Rename and Rotation

### Rename the Overlay

Keep the instance name stable and change `networkName` on every member.

Signed records are network-bound, so re-pair members after the rename.

### Rename the Instance

Renaming the attribute changes service, state, interface, and default ports.

Pin or migrate those values first when the identity must remain stable.

### Rotate an Identity

Replacing `private.key` changes the libp2p peer ID.

Update static authorization or pair the node again.

### Back Up an Identity

Back up the private key and generated pairing Nix together.

Restore the key with mode `0600` before starting the service.

Back up `membership-state.json` when the full learned mesh must restore offline.

See [Network Membership](membership.md) for state and upgrade behavior.

See [Overlay DNS](dns.md) for names, multi-instance behavior, and resolver
lifecycle.

## Evaluation Guards

The module rejects these configurations before activation:

- Mixed JSON and native Nix settings.
- Secrets or JSON config under `/nix/store`.
- Duplicate interfaces, listeners, sockets, or overlay addresses.
- Unsafe instance, interface, and state path names.
- Invalid discovery, relay, and packet-plane combinations.
- Inline private or membership keys.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Unit fails before start | `journalctl -u p2p-vpn-<instance>` |
| Identity changed | Restore the original `private.key` |
| No LAN peer | UDP `5353` and the libp2p port |
| Hostname does not resolve | `p2p-vpn dns status --instance <instance>` |
| Short name does not resolve | `resolvectl domain <interface>` |
| Name is ambiguous | `p2p-vpn dns list --instance <instance>` |
| No public fallback | Kademlia, AutoNAT, and relay status |
| No overlay route | Peer grant, `vpnIp`, or route ownership |
| Pairing output exists | Remove it or use `--force` deliberately |

Use [Operations](operations.md) for runtime commands and evidence capture.
